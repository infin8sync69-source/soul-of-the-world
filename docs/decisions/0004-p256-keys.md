# ADR-0004: P-256 as the mandatory signature curve

- Status: Accepted
- Date: 2026-10-09
- Related: SPEC-001, REQ-ID-03, REQ-ID-04

## Context
Keys should be hardware-protected on phones. Apple's Secure Enclave supports only NIST P-256 for signing. Android support for Ed25519 in hardware is not universal [Likely; varies by device]. The mobile predecessor already uses P-256 in the platform keystores.

## Decision
Identity and event signatures use ECDSA over P-256 with SHA-256, low-S enforced. Other curves may be added later as additional algorithms behind an algorithm identifier, but P-256 is always supported.

## Alternatives considered
- Ed25519: simpler and faster, but not hardware-backed on iOS.
- secp256k1: common in blockchain tooling; not hardware-backed on either platform.

## Consequences
ECDSA has pitfalls (nonce handling, malleability); deterministic nonces and low-S are required. P-256 keeps compatibility with `did:plc`-style rotation keys.

## Revisit when
Secure Enclave or Keystore support Ed25519 broadly, or post-quantum signatures become practical on mobile hardware.
